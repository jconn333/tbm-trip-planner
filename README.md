# TBM App

Flask app for TBM trip planning and owner/admin reservation management.

## Development setup

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

Run app:

```bash
python app.py
```

Run tests:

```bash
PYTHONPATH=. pytest -q
```

## Production hardening notes

- Set `APP_ENV=production`.
- Set a strong `FLASK_SECRET_KEY` (app will fail fast in production if unset/default).
- Set `DATABASE_URL` to your Postgres connection string.
- Keep `FLASK_DEBUG=false` in production.

Session and API protections:
- Session cookies are `HttpOnly`, `SameSite=Lax`, and `Secure` in production.
- Authenticated mutating API routes require `X-CSRF-Token`.
- `X-Request-Id` is returned on every response for tracing.
- Basic rate limiting is enabled on login/admin write endpoints.

## Deploy smoke checks

```bash
curl -sSf https://<your-host>/health
curl -sS https://<your-host>/api/admin/system-metrics -H "Cookie: <admin-session-cookie>"
```

Expected `/api/admin/system-metrics` fields in production:
- `env` is `production`
- `db.engine` is `postgres`
- `db.connected` is `true`
- `db.schema_version` is non-zero

Manual smoke flow:
1. Login as owner
2. Create pending reservation
3. Login as admin
4. Approve reservation
5. Owner submits change request
6. Admin approve/deny change request

## Render deployment runbook (Blueprint + Postgres)

This repo includes `render.yaml` as the source of truth for deployment.

### 1) Provision in Render
1. Push the repo with `render.yaml`.
2. In Render, create a Blueprint from the repo.
3. Confirm the web service has:
   - `runtime: python`
   - `startCommand: gunicorn wsgi:app`
   - `healthCheckPath: /health`
4. Confirm required env vars are configured:
   - `APP_ENV=production`
   - `FLASK_SECRET_KEY` (auto-generated by Blueprint)
   - `DATABASE_URL=<render-postgres-internal-url>`
   - `FLASK_DEBUG=false`
   - `LOG_LEVEL=INFO`
   - `TBM_HOME_TZ=America/New_York`
5. Set recommended vars before first deploy:
   - `TBM_ENABLE_RATE_LIMIT=true`
   - `TBM_BOOTSTRAP_ADMIN_EMAIL`
   - `TBM_BOOTSTRAP_ADMIN_NAME`
   - `TBM_BOOTSTRAP_ADMIN_PASSWORD` (temporary)

### 2) Migrate SQLite users/settings data into Postgres
If migrating existing local data:
1. Stop writes to your local app.
2. Run one-time migration script:
```bash
python scripts/migrate_sqlite_to_postgres.py \
  --sqlite-path ./tbm.sqlite3 \
  --postgres-url "$DATABASE_URL"
```
3. Redeploy or restart the service.

On startup, the app will run DB migrations automatically (`storage.init_db`) and seed defaults.

### 3) Post-first-success hardening
1. Remove `TBM_BOOTSTRAP_ADMIN_PASSWORD` from Render env vars after admin access is confirmed.
2. Leave bootstrap email/name only if you intentionally want bootstrap checks to continue.
3. Keep `EMAIL_ENABLED=false` unless SMTP settings are fully configured and tested.

## Postgres backup/restore note

Use Render Postgres backups/snapshots as the primary backup and restore mechanism.
